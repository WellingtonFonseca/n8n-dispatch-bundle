# n8n dispatch: status poll and unified History

The status poll (callback) that asks n8n about accepted dispatches, its settings and pause between calls, and the unified per-dispatch History (dispatch and callback entries as JSON).

## Status poll (callback)

An Email sent through Mautic's own mailer (n8ndispatch.mode `mautic`) has no tracking row and no callback: the screens read core's Stat, clicks and Do Not Contact instead (wiki/n8n-dispatch-email-direct.md). DispatchLogReader::dispatchOf returns null for it so the backfill skips it.

After a real dispatch Mautic asks n8n how it ended up and shows the answer on the Timeline card and in the history. Mautic asks (a command), n8n only answers. The contract for the n8n side, in Portuguese: `n8n-dispatch-bundle/docs/status-poll.pt-BR.md`.

### Unified history

Each dispatch has ONE history tied to its campaign log (the contact's History entry), in `n8n_dispatch_callback`. It survives a resend, which reuses the same log row and only drops the tracking rows.

```json
{
  "columns": "campaign_log_id (the link), kind ('dispatch' | 'callback'), outcome, ref_type + ref_value (the id n8n returned), tracking_id (callbacks only; kept after the tracking row is dropped), message (JSON), body_json (JSON), received_at.",
  "kind dispatch": "one per attempt to send, written when n8n answers (and for a test/paused step, with nothing sent). outcome: success | failed (accepted / refused), test, paused. body_json = {\"response\": <n8n's whole answer>} for the first dispatch, {\"reenvio\": {\"por\": <email>, \"em\": \"Y-m-d H:i\" UTC}, \"response\": ...} for a resend. The answer is kept accepted or not, in case it must be reprocessed. A transport failure of the FIRST dispatch writes no entry; of a resend it does (response = the error text).",
  "kind callback": "one per CHANGE of outcome the poll sees, plus the first 'pending' dated with the dispatch. The same outcome again only bumps check_count / last_checked_at. An error can turn into a success and the old error stays. message = {\"message\": <what n8n sent>} (null when none); body_json = the whole item n8n answered.",
  "tracking rows": "only the poll's queue (n8n_dispatch_tracking also has campaign_log_id). A resend deletes the old ones, so the poll stops asking about ids that no longer belong to the dispatch, and registers the new ones. StatusTracker::forget links history from before the link existed to the log first.",
  "table in the card": "Tipo (Disparo / Callback / Callback Meta) | Status | Id | Data | Mensagem, newest first; the details modal of the Dispatches screen is 1100 px wide for it.",
  "resend note": "the 'Reenvio feito em / Por' block sits under the status badges and above the Body (metadata n8ndispatch_resend, text); the pending callback of the new dispatch carries it as its message.",
  "backfill": "php bin/console n8ndispatch:status:backfill [--since-days=7] [--batch=500] [--dry-run] [--reset] [--no-poll]: builds the history of dispatches made before it existed from the campaign logs of the three actions (metadata is a PHP-serialized array). Each log with an 'n8ndispatch' block becomes the first 'dispatch' entry, dated with date_triggered; the ids of an accepted production dispatch are registered 'pending'; then n8n is asked (--no-poll skips that). --reset DELETES THE WHOLE HISTORY first, an explicit option on purpose; without it the command is idempotent.
```
