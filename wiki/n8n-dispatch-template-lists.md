# n8n dispatch: the status column of the SMS and HSM template lists

The Status column (icon badge that opens on hover, Ativar / Desativar in the row menu) of the SMS and HSM template lists. It follows core's toggle icon of the row. The twin of the list badge of MauticPatchesBundle, duplicated on purpose (../mautic-patches-bundle-5/wiki/patches-status-column.md). The alert log of the Alertas tab reuses its CSS under the class `.n8ndispatch-alert-status` (check / cross icons): wiki/n8n-dispatch-alerts.md.

## What it does

```json
{
  "template lists status": "Resources/views/{Hsm,Sms}Template/list.html.twig + Assets/js/template-status-toggle.js + n8ndispatch.css. The status is a column of its own, right after the menu column (`th/td.col-template-status`, header \"Status\" = mautic.n8ndispatch.template.status.column, printed by the twig, not sortable). The row has the n8n badge as an ICON badge (`.n8ndispatch-template-status`: a 22px circle with `ri-play-fill` on green `--production` or `ri-stop-fill` on red `--failed`, the word in `.n8ndispatch-template-status__text`, also the title and aria-label; on hover it opens to `max-width:140px` and the column widens (the browser lays the table out); the twin of MauticPatchesBundle's list badge, duplicated on purpose), core's toggle icon hidden (`#hsmTemplateTable / #smsTemplateTable i[class*=-publish-icon]`) and Desativar / Ativar as the FIRST item of the three-dots menu (a `customButtons` entry of list_actions, priority 300, `data-toggle=n8n-status`: without a data-toggle core adds `ajax` and navigates; only with sms:smses:editown/editother). The item CLICKS core's icon, so core sends the request and checks the permission; the script (MutationObserver) brings the badge and the item to the icon's state, the badge is orange with a spinner while core works. The text comes from data attributes the template prints, translated there (mautic.n8ndispatch.template.status.activate/deactivate). paintBadge in the script rebuilds the icon and the word on every state change (busy = spinner only). The description under the name is hidden by table (`#smsTemplateTable|#hsmTemplateTable td > div.text-muted`) because the badge no longer sits in that cell. These lists live in the plugin, so this is here and NOT in MauticPatchesBundle. The HSM list also has the Router and HSM Template columns after the name (sortable ht.router / ht.hsmTemplate, labels of the HSM form). Specs hsm-status, sms-status, hsm-list-columns; Tests/js/template-status-toggle.test.js.",
  "no column layout by script": "Assets/css/n8ndispatch.css: the cells of `#smsTemplateTable` and `#hsmTemplateTable` are `white-space:nowrap`, so the wider Status column makes the table scroll instead of squeezing the names; no script fixes the widths (template-status-toggle.js only paints the badge and the menu item). TRAP: with wrapping cells the open badge shrank the other columns, the rows re-wrapped and the badge slid from under the pointer (it flickered). Same rule as MauticPatchesBundle (../mautic-patches-bundle-5/wiki/patches-status-column.md, `badges box and layout`), duplicated on purpose."
}
```
